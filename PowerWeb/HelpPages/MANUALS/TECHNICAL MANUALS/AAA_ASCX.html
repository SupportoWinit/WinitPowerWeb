COMMENTI ALLA PARTE ASCX

  • Aggiunta di CAMPI di Altre Entità nella Lista dei CAMPI Visibili nella DATAGRID (Principale/Dettaglio)

    Quando si vogliono AGGIUNGERE alla DATAGRID (Principale e/o di Dettaglio [con/senza TAB) dei campi che NON appartengono alla sola Entità Principale che viene gestita in quella DataGrid ma stanno su una qualunque altra Entità collegata logicamente all'Entità Principale (tramite una relazione) o si vogliono aggiungere dei Campi CALCOLATI (come ad esempio nella DataGRid CANT dove c'è un Campo CLI_ID che fa riferimento all'Entità CLI o nllea DataGrid di CANT_VAR dove vogliamo mostrare un Campo Calcolato HASFRUCANT per indicare se quel record Cantiere ha/non ha Associazioni collegate) occorre
  • Verificare che questi Campi siano comunque definiti nelle corrispondenti EXTENSION dell'Entità a cui si stanno aggiungendo
    • DOMAIN
      • EXTENSION
        • CANT
          • public string Codice_Cliente 
            • quando è un Nome di un Campo di un altra Entity CHIAMARLO SEMPRE con il Nome del Campo dell'Entitità
              • per evitare di doverlo INSERIRE ANCHE nelle RESOURCES in Lingua
            • {
            •       get { return Cli.Codice_Cliente; }
            • }
        • Aggiungere le eventuali istruzioni necessaria alla loro COSTRUZIONE se sono Campi NON elementari
          • quando è un Nome di un Campo COSTRUITO/CALCOLATO chiamarlo comunque con il FINALE = ENTITA' (Col/Cant....)
            • OCCORRE ANCHE INSERIRLO nelle RESOURCES per la Gestione in Lingua
            • public string CognomeNome_Cli
            • {
            •       get { return String.Format("{0} {1}", Cli.Cognome_Cli, Cli.Nome_Cli); }
            • }
        • COL
          • public string CognomeNome_Col
            • {
            •        get { return new StringBuilder(Cognome_Col).Append(" ").Append(Nome_Col).ToString(); }
            • }
  • Verificare che gli eventuali Nuovi Nomi aggiunti nelle EXTENSION siano ANCHE presenti nelle Resources
    • COMMON
      • PowerWebResources
        • FLD_COGNOMENOME_CLI
        • FLD_COGNOME_NOME_COL
        • .........

  • I Campi XXXX_ID (ShowInCustomizationForm)

Lasciamo comunque i Campi di ID nella lista dei Campi gestibili nella DataGrid, mettendoli come "Visible=False"  in modo che nella
DataGRid Iniziale di Defaul NON Compaiano MA LASCIAMOLI ANCORA VISIBILI nella Finetra di Selezione dei Campi perchè
potrebbero servirci in Fase di Test per vedere che valore hanno durante i Test  !!!!!

Successivamente gli aggiungeremo nel Codice ascx l'opzione  ShowInCustomizationForm = "FALSE" in modo che NON
vengano più proposti come Campi Selezionabili da parte dell'Utente Finale

Quindi il Codice DIVENTERA' :
        <dx:GridViewDataTextColumn FieldName="Fil_Id" VisibleIndex="0" Visible="false" ShowInCustomizationForm="false">
      </dx:GridViewDataTextColumn>
In modo che nella DATAGRID di DEFAUL WINIT non vengano mostrati i Campi di ID e NON compaiano nemmeno nella Finestradi Selezione dei Campi aggiungibili da parte dell'Utente alla DataGrid.

  • Ordinamento dei Campi nella CUSTOMIZATIONFORM

L'ordinamento nella Finestra che permette di scegliere i Campi da visualizzare nella DATAGRID PRINCIPALE è quello ALFANUMERICO fatto sulla DESCRIZIONE IN LINGUA caricata nelle Resource
e NON DIPENDE
    nè dalla posizione occupata dai Campi nel codice ascx
    nè dal N° ssegnato come parametro di VisibleIndex="nnnn"

  • Ordinamento dei Campi nella DATA GRID PRINCIPALE

L'ordinamento di Visualizzazione nelle Colonne della DATA GRID PRINCIPALE dipende invece dal parametro VisibleIndex="nnnn" associato al campo nel codice ascx.

  • Ordinamento dei Campi nella DATA GRID DETTAGLIO (nelle Pagine SENZA TAB)

L'ordinamento di Visualizzazione nelle Colonne della DATA GRID di DETTAGLIO dipende dal parametro VisibleIndex="nnnn" associato al campo nel codice ascx.
